# Company OS V7 — Diagram Integration Plan

## Objective
Integrate the existing Nivy Company Visual System with Company OS V7 without creating a second diagram architecture.

## Phase 0 — Inventory and authority
- Confirm all existing Draw.io files.
- Identify canonical source, historical/reference files and duplicates.
- Map each diagram to Company OS V7 domains and governance objects.
- Record source and owner.

## Phase 1 — Reconcile with V7 standards
Validate terminology against:
- Company Master Standards
- Department Code Registry
- Document Type Registry
- Folder Structure Map
- Naming/Classification Rulebook
- Navigation Standard
- Governance/AI Policy

## Phase 2 — Cross-object coverage
Ensure diagrams collectively cover:
Company → Brand → Department → Role → Person → Responsibility → Goal → Plan → Initiative → Project → Task → Work → Output → KPI → Report → Review → Decision → Change → Record → Evidence.

Cross-cutting objects:
Customer, Vendor, Partner, Product/Service, Process, SOP, Document, System, AI Agent, Integration.

## Phase 3 — Diagram validation
For every master/child diagram:
1. Opens in Draw.io.
2. Uses canonical terminology.
3. Has scope and owner.
4. Identifies source/provenance.
5. Has parent/related diagrams where applicable.
6. Contains no secrets.
7. Has no conflicting duplicate relationship.
8. Is recorded in the tracker.

## Phase 4 — Canonical location decision
After validation, choose one authoritative location:
- Keep `docs/OWNER-CONTROL/05-VISUALS/`, with V7 pointing to it; OR
- migrate the complete visual system into `Company OS/Company-OS-v7/Diagrams/`.

Do not split authority between both locations.

## Phase 5 — Publication
Publish validated Draw.io sources and presentation derivatives only after canonical location and cross-diagram validation are complete.

## Acceptance
The diagram system is complete when every required V7 concept has exactly one canonical visual representation or an explicit documented reason why a diagram is unnecessary.
