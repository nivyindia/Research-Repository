# CSC Reuse-First Source Register

Last verified: 2026-10-03

## Rule

**REUSE → ADAPT → INTEGRATE → BUILD ONLY WHAT IS MISSING**

Do not create a new CSC training module when a reliable existing source already covers the requirement. Preserve provenance and distinguish official material from third-party training.

## Source priority

1. Official CSC / CSC Academy / CSC e-Governance source
2. Official central/state department or service portal
3. Existing official manuals, FAQs, circulars and operator documentation
4. Existing open-source/community material, after quality and licence review
5. Practical YouTube training, after workflow verification
6. Nivy-created SOP/content only for gaps

| UP department portals | Service workflows, eligibility, documents and notices | Reuse official process evidence | Official |
| PIB / MeitY CSC releases | Service-family and network baseline | Reuse as catalogue context, not as a live operator menu | Official government |

## Important distinction

- A source can be **reused as evidence** without being reused as an operator SOP.
- A YouTube video can be linked as practical training without treating its instructions as official.
- A service listed on NGSP can be catalogued without assuming it is delivered through CSC.
- A historical CSC service list must not be treated as today's live Digital Seva menu.

## Current high-value reuse targets

### CSC Academy
The current CSC Academy site explicitly provides VLE training and education/skill programmes. It also maintains a service list and course catalogue. Reuse these before building equivalent Nivy Academy lessons.

### Training videos
Use existing practical videos where they demonstrate the current portal/workflow. Replace stale videos when the official portal has changed.

### Government service documentation
For regulated services, use the current government portal/manual as the source of truth. Third-party videos are supplementary.

## Build-only-if-missing rule

Nivy should create new material only when:
- no usable current source exists;
- the source is incomplete for the operator's task;
- a state-specific workflow is missing;
- a QC/assessment layer is missing; or
- multiple existing sources need a new normalized SOP without changing the underlying official process.

## Provenance fields required

Every reused item should retain:
- source organization
- exact source title
- URL
- source type
- official / third-party status
- date checked
- licence/copyright note where applicable
- service(s) covered
- what was reused
- what was adapted
- verification status
