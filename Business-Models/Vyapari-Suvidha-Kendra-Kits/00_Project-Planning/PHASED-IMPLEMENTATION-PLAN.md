# File-by-File Outline Implementation Plan / हर फ़ाइल की outline बनाने की योजना

**Current stage:** Outline only — not full content.  
**वर्तमान चरण:** केवल outline — पूरा content अभी नहीं लिखना है।

## Rules / नियम
- हर listed file की outline में केवल मुख्य headings/topics होंगे; विस्तृत paragraphs, scripts और SOP steps बाद में।
- हर outline में Hindi (देवनागरी) पहले और English उसके तुरंत बाद होगा।
- Catalogue 1.52.docx current catalogue reference है; prices को अभी analyze या calculate नहीं करना है।
- Fees, commission, incentives, earnings, margins, settlement amounts और commercial promises को [PENDING APPROVED SOURCE] रखें।
- कोई proposed file अपने-आप create न करें। पहले current GitHub tree से existence जाँचें और फिर Keep / Merge / Proposed निर्णय लें।
- Shared policy या common data की एक authoritative master file होगी; दोनों kits उससे link करेंगी।

## Phase 1 — File inventory / फ़ाइलों की सूची की जाँच
1. GitHub पर project के actual paths और filenames verify करें।
2. हर path को Existing / Missing / Proposed / Merge candidate mark करें।
3. किसी file को delete, move या overwrite न करें।
4. नीचे दी गई file-wise outline को actual file list से reconcile करें।

## Phase 3 — Outline QA / outline की जाँच
- हर actual file का path और existence status match करें।
- हर file में purpose + concise headings + source/dependency + pending items दर्ज हों।
- Duplicates को merge/cross-reference करें; unnecessary files न जोड़ें।
- दोनों kits में role, service names, payment/support wording और version references consistent हों।
- Proposed files पर Keep / Merge / Drop निर्णय दर्ज करें।

## Phase 4 — Review and freeze / समीक्षा और freeze
1. सभी file-wise outlines का owner review।
2. Corrections को इसी register/plan में दर्ज करना।
3. Approved outline baseline को freeze करना।
4. उसके बाद ही source mapping और full-content drafting शुरू करना।

## अभी नहीं करना है / Do not do yet
- Full paragraphs, final scripts या detailed SOP instructions लिखना।
- Prices, commissions, incentives, margins या earnings calculate करना।
- Unverified support, lead generation, refund, timeline या income promises करना।
- Review से पहले files delete, move, rename या bulk-create करना।

## Definition of done / पूरा होने की शर्त
हर actual file के लिए concise topic outline दर्ज हो; proposed assets पर decision हो; duplicate coverage का reference हो; pending source/approval clearly marked हो; और outline review के लिए तैयार हो।
