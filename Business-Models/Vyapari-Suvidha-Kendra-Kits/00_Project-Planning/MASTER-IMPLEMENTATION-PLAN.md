# Master Implementation Plan / मुख्य कार्यान्वयन योजना

## 0. Mandatory bilingual documentation standard / अनिवार्य द्विभाषी दस्तावेज़ी मानक

**हिंदी:** इस प्रोजेक्ट के अंतर्गत बनाई या संशोधित की जाने वाली हर फ़ाइल हिंदी और English दोनों में होगी। हर शीर्षक, अनुभाग, निर्देश, विवरण, checklist item, table heading/entry, FAQ, script और template में पहले देवनागरी लिपि में हिंदी लिखें; उसके तुरंत बाद उसी अर्थ का English अनुवाद दें। हिंदी सामग्री पहले आएगी और English उसका अनुसरण करेगी।

**English:** Every file created or revised under this project must be bilingual in Hindi and English. For every heading, section, instruction, description, checklist item, table heading/entry, FAQ, script, and template, write the Hindi version first in Devanagari script, followed immediately by the equivalent English translation. Hindi always comes first, followed by English.

**हिंदी उदाहरण (Hindi Sample)**

> **"वसुधैव कुटुम्बकम् का अर्थ है कि पूरी धरती ही हमारा परिवार है।"**

**English translation:** “Vasudhaiva Kutumbakam means that the entire Earth is one family.”

### Formatting rules / प्रारूप के नियम
- **हिंदी:** पहले पूरा हिंदी वाक्य/अनुच्छेद दें, फिर उसके ठीक नीचे English अनुवाद दें।  
  **English:** Put the complete Hindi sentence/paragraph first, then its English translation directly below it.
- **हिंदी:** लंबे दस्तावेज़ में हर छोटे अनुभाग या तार्किक इकाई को इसी क्रम में लिखें; पूरा हिंदी दस्तावेज़ और उसके बाद पूरा English दस्तावेज़ न रखें।  
  **English:** In long documents, repeat this order for each section or logical unit; do not put the entire Hindi document first and the entire English document afterward.
- **हिंदी:** तालिकाओं में शीर्षक और सामग्री दोनों भाषाओं में दें; जहाँ जगह सीमित हो, प्रत्येक cell में हिंदी पहले और English उसके बाद रखें।  
  **English:** Make table headings and content bilingual; where space is limited, put Hindi first and English second within each cell.
- **हिंदी:** तकनीकी IDs, code, URLs, repository paths, filenames और standard product names को आवश्यकतानुसार English में रखा जा सकता है, लेकिन उनका विवरण हिंदी-प्रथम द्विभाषी होना चाहिए।  
  **English:** Technical IDs, code, URLs, repository paths, filenames, and standard product names may remain in English where needed, but their explanations must follow the Hindi-first bilingual format.
- **हिंदी:** किसी source का मूल नाम या उद्धरण आवश्यक हो तो उसे जस का तस रखें और उसके साथ हिंदी/English में स्पष्टीकरण दें।  
  **English:** Preserve a source's original title or quotation when necessary, and provide its explanation in Hindi and English.
- **हिंदी:** यदि किसी file में केवल एक भाषा का स्रोत उपलब्ध है, तो दूसरी भाषा में faithful translation दें; तथ्य या व्यावसायिक शर्तें न गढ़ें।  
  **English:** If a source file is available in only one language, provide a faithful translation into the other language; do not invent facts or commercial terms.

## 1. Objective / उद्देश्य
Create a complete, source-backed documentation system for:
- **Partner Welcome Kit** — for Franchisees/Retailers joining and operating the service centre.
- **Distributor Field Meeting Kit** — for Distributors recruiting, qualifying and onboarding Franchisees/Retailers.
- **Shared Master References** — common service catalogue, approved pricing/commission matrix, approvals, version control and audit records.

**हिंदी:** सबसे पहले हर planned file की outline, phased implementation plan और progress tracker तय करना है। अंतिम सामग्री का निर्माण source audit और outline review के बाद होगा।  
**English:** First define the outline of every planned file, the phased implementation plan, and the progress tracker. Final content production follows the source audit and outline review.

## 2. Final deliverables / अंतिम deliverables
1. Planning hub containing all plans and the progress tracker.
2. File-by-file outline register for every proposed document.
3. Source inventory and gap analysis against Partner Welcome Kit, Distributor Field Kit, Training Folder and relevant approved business documents.
4. Migrated/organized source materials with provenance and duplicate handling.
5. Verified shared master references and commercial matrix.
6. Long-format master guides for each audience.
7. Compact offline booklets: Partner Welcome Kit (target 8–10 pages) and Distributor Field Meeting Kit (target 9–12 pages).
8. Supporting sales, onboarding, training, communications, marketing, reporting and SOP assets.
9. Approval and release record for print/offline versions.
10. Every deliverable must follow the Hindi-first bilingual standard defined above.

## 3. Audience and content boundary / पाठक-वर्ग और सामग्री की सीमा
### Partner Welcome Kit / पार्टनर स्वागत किट
**हिंदी:** यह बताए कि व्यवसाय क्या है, कौन-सी सेवाएँ उपलब्ध हैं, कौन-से दस्तावेज़ चाहिए, onboarding और customer service कैसे होगी, सत्यापित शुल्क/कमाई क्या है, भुगतान और सहायता कैसे मिलेगी।  
**English:** Explain the business, available services, required documents, onboarding and customer-service workflows, verified fees/earnings, payments, and support.

### Distributor Field Meeting Kit / डिस्ट्रीब्यूटर फील्ड मीटिंग किट
**हिंदी:** यह बताए कि उपयुक्त prospects कैसे खोजें, field meeting कैसे करें, business model और अलग-अलग कमाई कैसे समझाएँ, आपत्तियों का उत्तर कैसे दें, prospects को qualify करके onboarding तक कैसे पहुँचाएँ।  
**English:** Explain how to find suitable prospects, conduct field meetings, explain the business model and separate earnings, handle objections, qualify prospects, and hand them over for onboarding.

### Shared references / साझा संदर्भ
Maintain one approved source of truth for service availability, customer pricing, statutory/third-party charges, company/partner/distributor shares, settlement rules, effective dates, approvals and policy changes.

## 4. Non-negotiable rules / अनिवार्य नियम
- No fabricated or assumed commercial terms / कोई भी शुल्क, कमीशन या व्यावसायिक शर्त अनुमान से न लिखें।
- No earnings guarantees unless explicitly supported by approved written policy / लिखित स्वीकृत नीति के बिना कमाई की गारंटी न दें।
- No claims about company leads, online marketing, conversion support or territory protection until verified / कंपनी की leads, online marketing या territory protection के दावे सत्यापित होने तक न करें।
- Explain Franchisee/Retailer share separately from Distributor share / Franchisee/Retailer और Distributor की कमाई अलग-अलग दिखाएँ।
- Mark unknowns and record them in the decision register / अज्ञात बातों को स्पष्ट चिह्नित कर decision register में दर्ज करें।
- Keep customer personal data and completed KYC documents outside GitHub / ग्राहक का निजी डेटा और भरे हुए KYC दस्तावेज़ GitHub में न रखें।
- Preserve source provenance and archive superseded versions / स्रोत का रिकॉर्ड रखें और पुराने versions archive करें।
- Every file must follow Hindi first, English immediately after / हर फ़ाइल में पहले हिंदी और तुरंत बाद English अनुवाद अनिवार्य है।

## 5. Definition of done / काम पूरा होने की शर्तें
The project is complete only when every planned file has an outline, relevant sources have been audited, conflicts/gaps are recorded, commercial facts are approved, long guides and short booklets are reviewed, required assets are linked, and each release has a version/status. Every released file must also pass the bilingual-format check.

**हिंदी:** कोई file केवल लिख देने से complete नहीं मानी जाएगी। उसकी source verification, bilingual check और आवश्यक approval भी पूरा होना चाहिए।  
**English:** A file is not complete merely because it has been drafted. Source verification, bilingual review, and required approvals must also be completed.

## 6. Status vocabulary / स्थिति के मानक
- **Not started** — काम शुरू नहीं हुआ / Work has not started.
- **In progress** — काम जारी है / Work is underway.
- **Needs source audit** — स्रोत की जाँच बाकी है / Source audit is pending.
- **Needs confirmation** — पुष्टि आवश्यक है / Confirmation is required.
- **In review** — समीक्षा जारी है / Under review.
- **Approved** — अधिकृत स्वीकृति मिली / Approved by an authorized reviewer.
- **Blocked** — किसी dependency के कारण रुका / Blocked by a dependency.
- **Complete** — acceptance criteria पूरे / Acceptance criteria met; approval is still separately required where applicable.

## 7. Governance / नियंत्रण व्यवस्था
The Progress Tracker is the live execution record. The File Outline Register defines intended coverage. The Source Audit Plan controls source inspection and migration. The Decisions and Open Questions file records unresolved facts. Update these records when scope or sequencing changes. Apply the bilingual standard to all newly created and revised files.
