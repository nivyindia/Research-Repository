# Pilot and Acceptance Tests

## Pilot objective

Prove that the discovery engine can repeatedly find candidates and distinguish useful matches using job-relevant evidence.

## Initial pilot roles

Computer/Data Operator; Digital Marketing/VA; Accounting/Bookkeeping; AI/Automation; BDE/Sales.

Use multiple source families for each role where practical.

## Pilot sequence

1. Source candidates
2. Capture source/campaign
3. Intake
4. Deduplicate
5. Eligibility
6. Structured screen
7. Practical test
8. Three consistency tasks for selected candidates
9. Training/remediation where appropriate
10. Internship/work trial
11. Outcome capture
12. Source analysis
13. Process revision

## Acceptance tests

### Identity
- repeat applications link to one person
- multiple applications can exist for one person

### Discovery
- every candidate has source and campaign
- provenance is retained

### Qualification
- every pilot role has a Success Profile
- claims are separated from evidence
- common gates are consistent

### Reliability
- repeated work is observed
- deadlines and communication are recorded

### Operations
- reviewer sees next action
- reminders work
- status is traceable

### Analytics
- source-to-stage conversion is available
- source-to-success outcome is available

### Safety
- candidate PII is not committed to GitHub
- sensitive/protected attributes are not used as capability proxies
- AI-assisted decisions have human review

## V1 release criteria

Release only when the end-to-end flow works with real candidates, five role families have usable profiles, source attribution works, duplicates are controlled, practical evidence is captured, repeated-task observation works and downstream outcomes are recorded.

## Post-pilot review

Document false positives, false negatives, source-quality differences, assessment problems, candidate drop-off, recruiter workload, automation failures and role-profile gaps. Create V1.1 backlog.
